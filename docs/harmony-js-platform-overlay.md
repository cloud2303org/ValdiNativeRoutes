# Harmony JavaScript platform overlay correction

The maintained fork already fixes flat property-list removal so only complete
key/value pairs are searched. The staged `.tools/harmony/upstream` copy still
contained the original `indexOf` implementation on November 3, 2026.

An actual compiled production-function probe reproduced the difference:
removing `harmonyClass` from `['name', 'harmonyClass', 'width', 100]` returned
`width` and left `['name', 100]` in the old stage. The maintained implementation
returns undefined and preserves the attributes.

The source correction is in `scripts/harmony/apply-platform.mjs`. It generates
the already reviewed maintained-fork utility from the immutable pin, with the
same exact bytes. The transformation is idempotent and fails if the expected
source body does not match.

`pinnedInputs()` in `tools/valdi-rolldown/harmony-business.ts` now includes this
utility in its reproducible overlay inputs. A consumed transformed utility must
match the freshly reconstructed pin-plus-script output. An arbitrary edit to
that transformed input remains rejected; the filename is not exempted from
verification.

The verifier also continues accepting unmodified pinned files. This follow-up
does not retroactively change the old staging tree or require every pinned
source consumer to use the Harmony overlay.
